# Findings and conclusions — 2026-09-09 session

Status: decision record. Everything below is evidenced by sealed preregs,
committed evidence rows, PRs, or issue comments in this repo. This document

## Part 1 — Findings

**F1 — Pricing was wrong in a specific, expensive way.**
`glm-5p3-flash` carried GLM 5.2 Fast's prices ($2.10/$0.39/$6.60) from
2026-08-28 to 2026-09-09 — flash-lane metering ran ~14x too high
(Flash/Fast row confusion, #83 M3). `deepseek-v4-pro` matched no current
tier; the zcode pricing twin was missing the rotated roster entirely and
priced fast-tier rows from their base models. Fixed in PR #87 with dated
catalog pins + Flash/Fast tier-relation + roster-coverage fixtures. Side
validation: the corrected table predicts the flash arm's metered cost to the
cent, where the old table would have printed ~14x.

**F2 — The acceptance path had real, reproduced holes; most are now closed.**
The 2026-09-07 review (#83) reproduced A01–A14 against the deployed revision.
Closed today: **A12** (string booleans routed work to the flash lane — PR
#88), **A03/A04** (wrong task/workspace accepted with reused state — PR #93),
**A13** (truncated usage metered as $0 — PR #94), **A07/A09** in the ZCode
harness (verifier substitution accepted bad source; unreadable fail-open
evidence read as clean — PR #95, with probe-evidence conversions). Open,
deliberately: A01/A02/A06 (timeout/live-writer lifecycle — runner M1),
A05/A14 (verifier environment — runner M2, now gated on F4), A08/C02
(ZCode dispatch reservation / keyed hashes — folded into runner M1),
A10/A11 (ZCode substring guard / case-sensitivity — reported, not
reproduced on this Windows box).

**F3 — The rotated roster is fully measured and dominates its predecessors.**
EVAL-006 (#91, sealed `PREREG-v3-rotation`): glm-5p3 30/30 hidden at
$0.0739/hidden-pass (24% cheaper than glm-5p2 at equal quality); glm-5p3-flash
29/30 at $0.0096/hidden-pass proctored — the cheapest measured arm in the
program. STOP-on-cost holds a second time: no routing headroom on this
workload class. Owner sealed: keep both lanes.

**F4 — The proctor's dispatch wrapper is a measured overhead, not a saving.**
M4-early, pulled forward and run under sealed rules
(`PREREG-plain-vs-proctored`, amendment `eb9830d`, rows `56f2d19`): the plain
arm (delegate only, same model/transport/prompts/timeouts/fixtures, no
control plane) beat the proctored arm on every axis — **$0.0081 vs $0.0096
per hidden-pass (16% cheaper), 30/30 vs 29/30 quality, 885s vs 2001s wall.**
Workers under the proctor consumed 4.58M tokens vs 3.74M (~28k/run more) on
identical prompt text; the runner passes the prompt verbatim
(`runner.py:940`), so this is not augmentation. Cause unestablished —
candidates: control-plane files in the worker's tree (`task.json` written
in-workspace by pilot; the plain driver's prompt file is outside it), and
between-session variance (the arms were not interleaved). Ruled per the
precommitted interpretation: **the dispatch path needs rework before any
economic adoption claim; investigate before building M2.**

**F5 — What was NOT measured.** Neither arm recreated the proctor's original
economic thesis (leader-context protection: the leader session is 96% of
spend). In both arms the worker owned the codebase. The routed-vs-
direct-strong comparison — the only remaining experiment that could come out
in the proctor's economic favor — stays unopened. Trust value (receipts,
sealed verifiers) was deliberately unpriced: on self-grading fixtures the
checker catches wrong answers in both arms, so the gate has nothing to do.
Its value is production work where "looks done" costs real money.

**F6 — Process findings.** Prereg discipline worked as designed: the
precommitted interpretation forced an inconvenient ruling; the sealed-before-
run rule caught a driver bug honestly (one ~$0.01 dispatch crashed
pre-metering, amended on the record, no fabricated rows). The
probes-with-positive-controls pattern (PR #89) made NOT-REPRODUCED verdicts
meaningful and converted cleanly into regression tests (PR #95).

## Part 2 — Conclusions

The proctor's value pillars, measured:

| Pillar | Verdict | Evidence |
|---|---|---|
| Routing by task shape | **zero, twice confirmed** | #30, #91 (STOP) |
| Dispatch wrapper economics | **negative ~12–16%** | F4 |
| Trust boundary (receipts, seals, identity) | **standing — and now real** | F2 fixes; production certification |
| Accounting truthfulness | **standing** | F1, F2 (A13) |
| Leader-context protection | **unmeasured** | F5 |

One fixed worker wins (STOP, twice). One **thin gate** wins from here: the
gate's job is to grade and account, not to chaperone. Elaborate machinery
around capable cheap models costs more than it saves on the task classes
this repo can measure.

## Part 3 — Decision: catalog-dispatched subagents

Convert the tool so **kimi-code-cli and ZCode can start a subagent of a
specified model** — "start subagent with model [x]", [x] any model in the
harness catalog — with the lane table, task features, stagnation ladders and
tier gates retired from the live path.

**Kept** (the standing pillars): delegate transport (isolated homes,
envelopes, wire metering), the runner's verify/accept/identity/seals as the
optional trust gate for production tasks, truthful accounting (A13
semantics), budgets as simple per-dispatch caps.

**Dropped from the live path:** `lane_for`/features classification, frozen
lane table, lateral-switch/stagnation machinery, tier escalation (retained
in-repo as the frozen experiment record they were).

**Design requirements (each traces to a finding):**

1. *Drift-proof catalog* (F1, #23): the model id is validated against the
   harness's live model config at dispatch time; unknown/rotated ids refuse
   loudly, never 404 mid-run. Unpriced models meter as unknown, never $0.
2. *Read-only by default* (roster doctrine): dynamic dispatch defaults to
   read-only; write access is an explicit flag.
3. *No control-plane files in the worker's tree* (F4's leading suspect):
   prompt via external task-file; the neutrality acceptance below is what
   proves this mattered.
4. *No unmanaged nesting* (#86's warning class): delegate refuses
   `--model`/`--write` spawns from inside a worker (child env marker).
5. *Neutrality acceptance criterion* (F4): interleaved plain vs model-mode
   batch on the v3 corpus — cost/tokens/wall within noise. The conversion is
   not done until this passes.

## Part 4 — Plan

- **Phase 1 — kimi-code**: `delegate.py --model <id>` (safe defaults:
  timeout, env allowlist, isolated home, stdout caps; `--write` opt-in;
  live catalog validation); `catalog` command (models + prices + limits,
  unpriced flagged); skill rewritten to "start subagent with model X", with
  the runner gate documented as the production path; runner untouched
  except the lane table leaving the default flow.
- **Phase 2 — ZCode**: spike the Agent tool's model surface; then either
  gate-validate a native model field, or sync `m-<model>` subagent entries
  into ZCode's machine-local config from the catalog. The gate keeps the
  per-task dispatch cap and the A07/A09 fixes; tier/stagnation enforcement
  is removed. `harnesses/zcode/AGENTS.md` rewritten for the new flow.
- **Phase 3 — validation**: interleaved neutrality batch (amended M4-early
  protocol, ~$0.50); full suites; installers; README/skill.
