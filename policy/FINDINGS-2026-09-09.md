## Part 1 — Findings

**F1 — Pricing was wrong in a specific, expensive way.**
`glm-5p3-flash` carried GLM 5.2 Fast's prices ($2.10/$0.39/$6.60) from
2026-08-28 to 2026-09-09 — flash-lane metering ran ~14x too high
(Flash/Fast row confusion, #83 M3). `deepseek-v4-pro` matched no current
tier; the zcode pricing twin was missing the rotated roster entirely and
priced fast-tier rows from their base models. Fixed in PR #87 with dated
catalog pins + Flash/Fast tier-relation + roster-coverage fixtures. Side
validation: the corrected table predicts the flash arm's metered cost to the
cent, where the old table would have printed ~14x.

**F2 — The acceptance path had real, reproduced holes; most are now closed.**
The 2026-09-07 review (#83) reproduced A01–A14 against the deployed revision.
Closed today: **A12** (string booleans routed work to the flash lane — PR
#88), **A03/A04** (wrong task/workspace accepted with reused state — PR #93),
**A13** (truncated usage metered as $0 — PR #94), **A07/A09** in the ZCode
harness (verifier substitution accepted bad source; unreadable fail-open
evidence read as clean — PR #95, with probe-evidence conversions). Open,
deliberately: A01/A02/A06 (timeout/live-writer lifecycle — runner M1),
A05/A14 (verifier environment — runner M2, now gated on F4), A08/C02
(ZCode dispatch reservation / keyed hashes — folded into runner M1),
A10/A11 (ZCode substring guard / case-sensitivity — reported, not
reproduced on this Windows box).

**F3 — The rotated roster is fully measured and dominates its predecessors.**
EVAL-006 (#91, sealed `PREREG-v3-rotation`): glm-5p3 30/30 hidden at
$0.0739/hidden-pass (24% cheaper than glm-5p2 at equal quality); glm-5p3-flash
29/30 at $0.0096/hidden-pass proctored — the cheapest measured arm in the
program. STOP-on-cost holds a second time: no routing headroom on this
workload class. Owner sealed: keep both lanes.

**F4 — The proctor's dispatch wrapper is a measured overhead, not a saving.**
M4-early, pulled forward and run under sealed rules
(`PREREG-plain-vs-proctored`, amendment `eb9830d`, rows `56f2d19`): the plain
arm (delegate only, same model/transport/prompts/timeouts/fixtures, no
control plane) beat the proctored arm on every axis — **$0.0081 vs $0.0096
per hidden-pass (16% cheaper), 30/30 vs 29/30 quality, 885s vs 2001s wall.**
Workers under the proctor consumed 4.58M tokens vs 3.74M (~28k/run more) on
identical prompt text; the runner passes the prompt verbatim
(`runner.py:940`), so this is not augmentation. Cause unestablished —
candidates: control-plane files in the worker's tree (`task.json` written
in-workspace by pilot; the plain driver's prompt file is outside it), and
between-session variance (the arms were not interleaved). Ruled per the
precommitted interpretation: **the dispatch path needs rework before any
economic adoption claim; investigate before building M2.**

*QC round 1 (2026-09-10, glm-5.3 adversarial worker) sharpened F4:* the
point estimate is −16% but the 95% bootstrap CI on the cost ratio spans
parity ([0.99, 1.43]; one-sided P(N cheaper) = 0.97; n=30 underpowered —
Welch p ≈ 0.16). The ruling stands — the precommitted +10% margin fired on
the point estimate and is robust to including the crashed ~$0.01 dispatch
(12.2%) — but it is a point-estimate ruling, reported here with its
interval. The wall headline compared different scopes: the proctored arm's
`wall_time_s` spans the full loop (init→record + hidden check,
`pilot.py:289–380`), the plain arm's spans the delegate run only —
orchestration overhead is real, the 2.3× conflates scopes. The task.json
mechanism gained direct support: per-run usage records 6.37 vs 5.30 with
near-identical per-record cache reads and ~+420 resident tokens — the
signature of one extra turn reading a ~400–500-token in-tree control-plane
file.

*E-mech (2026-09-10, sealed `PREREG-model-mode`) killed the task.json
hypothesis and reattributed F4 entirely:* a single-variable A/B on the
existing proctored path — task.json in-tree vs relocated outside the
workspace, 30 runs per arm — found the arms indistinguishable on the
one-extra-turn signature (6.00 vs 5.90 usage-records/run, Welch t = 0.135,
p = 0.89). **The F4 16% was an artifact of run order**: the M4-early arms
ran sequentially, not interleaved, and between-session variance carried the
whole delta. The proctored dispatch path was never more expensive per-run.
F4's ruling ("dispatch path needs rework") is superseded by this finding:
the dispatch path was fine; the comparison was confounded. E-ship (same
prereg, 120 interleaved runs) then confirmed the converted model-mode path
is cost-equivalent to plain delegate dispatch (TOST 90% CI
[−$0.0009, +$0.0010] inside the frozen ±$0.0012 margin, quality 59/60
both arms). See #96 comment 5629276384 for the full tables.

**F5 — What was NOT measured.** Neither arm recreated the proctor's original
economic thesis (leader-context protection: the leader session is 96% of
spend). In both arms the worker owned the codebase. The routed-vs-
direct-strong comparison — the only remaining experiment that could come out
in the proctor's economic favor — stays unopened. Trust value (receipts,
sealed verifiers) was deliberately unpriced: on self-grading fixtures the
checker catches wrong answers in both arms, so the gate has nothing to do.
Its value is production work where "looks done" costs real money.

**F6 — Process findings.** Prereg discipline worked as designed: the
precommitted interpretation forced an inconvenient ruling; the sealed-before-
run rule caught a driver bug honestly (one ~$0.01 dispatch crashed
pre-metering, amended on the record, no fabricated rows). The
probes-with-positive-controls pattern (PR #89) made NOT-REPRODUCED verdicts
meaningful and converted cleanly into regression tests (PR #95).

## Part 2 — Conclusions

The proctor's value pillars, measured:

| Pillar | Verdict | Evidence |
|---|---|---|
| Routing by task shape | **zero on the measured corpus** (bounded ~30s tasks, quality-tied); **long-task break-even favors cheap-first + escalation beyond X\* = ln(b/s)/ln(q)** — q unmeasured | #30, #91 (STOP); the break-even analysis in README |
| Dispatch wrapper economics | **flat — F4's −16% was a run-order artifact (E-mech); converted path TOST-equivalent to plain (E-ship)** | F4, corrected by E-mech/E-ship |
| Trust boundary (receipts, seals, identity) | **standing — and now real** | F2 fixes; production certification |
| Accounting truthfulness | **standing** | F1, F2 (A13) |
| Leader-context protection | **unmeasured** | F5 |

On the measured corpus one fixed worker wins (STOP, twice). But that corpus is
single-unit tasks where every tier was quality-tied — the regime where routing
cannot help by construction. The task-size break-even (README, "The routing
break-even") shows cheap-first-with-escalation beats fixed-strong at ANY size
(overhead ≈ $0, price ratio ≈ 16x) and beats fixed-cheap once per-unit failure
compounds past the threshold — ~13–83 benchmark-units depending on per-unit
reliability. The owner decision (2026-09-10): **the gated path — flash-first,
escalating to glm-5p3 then kimi-k3 on recorded stagnation — stays as the
default for substantial work.** The gate's job is to grade, account, and
escalate on evidence; the catalog surface (`--model`) serves consults and
one-shots.

## Part 3 — Decision: catalog-dispatched subagents

Convert the tool so **kimi-code-cli and ZCode can start a subagent of a
specified model** — "start subagent with model [x]", [x] any model in the
harness catalog — with the lane table, task features, stagnation ladders and
tier gates retired from the live path.

**Kept** (the standing pillars): delegate transport (isolated homes,
envelopes, wire metering), the runner's verify/accept/identity/seals as the
optional trust gate for production tasks, truthful accounting (A13
semantics), budgets as simple per-dispatch caps.

**Dropped from the live path:** `lane_for`/features classification, frozen
lane table, lateral-switch/stagnation machinery, tier escalation (retained
in-repo as the frozen experiment record they were).

**Design requirements (each traces to a finding; amended 2026-09-10 after
adversarial QC round 1):**

1. *Drift-proof catalog* (F1, #23) — specified precisely: the model id is
   validated by a **live read of kimi's actual config at dispatch time**
   (`[models]` keys), never a synced or pinned copy — a second catalog
   surface is exactly what desynced on 2026-08-28. Caveat stated honestly:
   config presence ≠ serving (glm-5p3 was listed and still 404'd that
   morning); serving failures surface as provider failures in the envelope.
   The `catalog` command prints pricing per model and flags models with no
   pricing row as *meters-as-unknown*; a mispriced-but-present row is a
   stated residual, detectable only by re-verification (the dated notes in
   `pricing.yaml` are the record).
2. *Write boundary, pinned* — `--write` exists only in model-mode, defaults
   false; roster agents keep their own `write_allowed` unchanged (one gate
   per surface). `write_allowed` remains envelope metadata by the
   delegate's own doctrine (`delegate.py:420`); the enforceable protections
   are transport-level (env allowlist, isolated home, job-object
   kill-on-close, no breakaway in the model template). Refusal output lists
   same-family live alternatives so a mid-week rotation degrades to a
   one-line fix, not a bricked pipeline; production pipelines stay on the
   runner path, which owns the recorded rollback doctrine.
3. *No control-plane files in the worker's tree* (F4's mechanism, now with
   a direct token signature) — prompt via external task-file. Attribution
   is E-mech's job (below), not asserted here.
4. *No unmanaged nesting* (#86's warning class) — the child marker
   (`PROCTOR_CHILD=1`) is **injected** into the child env by delegate (as
   `KIMI_CODE_HOME` is), never inherited; a delegate running with the
   marker refuses `--model` and `--write` spawns.
5. *Production-pattern refusal, ported* (QC C1) — model-mode dispatch
   refuses prompts matching the known production-entrypoint denylist (twin
   of `runner.PRODUCTION_RUNNER_PATTERNS`) and points at the runner gate.
   The default for production work is the gated runner path — **decided,
   not recommended**.
6. *Shipping acceptance = preregistered equivalence, not "within noise"*
   (QC E1/B2) — two experiments, both sealed before runs: **E-mech**
   (single-variable: existing proctored path, `task.json` relocated outside
   the workspace vs in-tree; interleaved; primary metric usage-records/run —
   the one-extra-turn signature; secondary cost/tokens) and **E-ship**
   (converted model-mode path vs plain, interleaved, TOST on per-run cost
   with a frozen margin at n sized to the F4 effect). A pass on E-ship
   ships; E-mech attributes. Neither claims what the other shows.

## Part 4 — Plan

- **Phase 1 — kimi-code**: `delegate.py --model <id>` (safe defaults:
  timeout, env allowlist, isolated home, stdout caps; `--write` opt-in;
  live catalog validation); `catalog` command (models + prices + limits,
  unpriced flagged); skill rewritten to "start subagent with model X", with
  the runner gate documented as the production path; runner untouched
  except the lane table leaving the default flow.
- **Phase 2 — ZCode**: spike the Agent tool's model surface; then either
  gate-validate a native model field, or sync `m-<model>` subagent entries

  per-task dispatch cap and the A07/A09 fixes; tier/stagnation enforcement
  is removed. `harnesses/zcode/AGENTS.md` rewritten for the new flow.
