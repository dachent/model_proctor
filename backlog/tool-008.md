1. No owner-action item without a leader-checkable verification hook (folder/process/file state) — leader checks before asking the owner for status.
2. The leader always drives session setup (open browser/page/tool); the owner only authenticates.
3. Instructions templated from prior runs must be validated against current reality (counts, names, boundaries) BEFORE being issued.
4. Every owner-action item carries an explicit done/cancel checkpoint; dependent work stays blocked until it fires.
